**CRITICAL ordering notes:**
- `SDL3_FrameStateSystem` is placed in `SDL3_Window_use()`, NOT in `SDL3_FrameLoop_use()`. This is because FrameStateSystem monitors window states (it checks if all windows are closed) and must register AFTER WindowStateSystem. Since CELS system execution order within a phase is determined by registration order, placing both in Window_use() guarantees WindowStateSystem runs before FrameStateSystem within OnLoad. Per RESEARCH pragmatic solution: "the 'all windows closed -> stop running' logic belongs to the window provider."
- `SDL3_FrameLoop_use()` only registers `SDL3_FrameState` (the state singleton). The FrameState system is bundled with Window because it depends on window state queries.
- The existing `cels_register(SDL3_FrameState, SDL3_InputSystem)` line combines FrameState and InputSystem. After partitioning, FrameState goes to `SDL3_FrameLoop_use()` and InputSystem goes to `SDL3_Input_use()`. The guard flags prevent double-registration of SDL3_FrameState if both are called.

Add SDL3_use() implementation:

```c
void SDL3_use(const SDL3_Config* config) {
    /* Apply config before registration */
    if (config) {
        if (config->on_error) {
            sdl3_set_error_callback(config->on_error);
        }
        if (config->sdl_init_flags) {
            sdl3_set_init_flags(config->sdl_init_flags);
        }
    }

    /* Register all providers in correct order */
    SDL3_Init_use();
    SDL3_FrameLoop_use();
    SDL3_Input_use();
    SDL3_Window_use();
    SDL3_Renderer_use();
    SDL3_Textures_use();
    SDL3_Text_use();
}
```
