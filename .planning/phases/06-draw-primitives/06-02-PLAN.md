The example should demonstrate:

**World composition:**

```c
CEL_Compose(World) {
    SDL3Window(.title = "Draw Primitives", .width = 800, .height = 600,
               .context = true, .target_fps = 60) {}
}
```

**ShapeRenderer system (OnRender phase):**
Queries SDL3_Renderer, gets the vtable via `sdl3_renderable()`, and draws shapes that visually prove z-ordering:

1. **Background panel** (z=0): Large dark gray filled rect covering center area, e.g. `{100, 50, 600, 500}` with color `{40, 40, 40, 255}`.

2. **Grid lines** (z=0): Several horizontal and vertical lines across the panel area in a muted color like `{60, 60, 60, 255}`. These should be at z=0 (same as background), so they render in creation order AFTER the background (confirming tiebreaker works).

3. **Colored filled rects** (z=1): Two or three filled rectangles at different positions with distinct colors:
   - Red rect: `{150, 100, 180, 120}` with `{220, 50, 50, 255}`
   - Blue rect: `{350, 200, 180, 120}` with `{50, 100, 220, 255}`
   - Green rect: `{250, 150, 180, 120}` with `{50, 180, 50, 255}` -- partially overlapping red and blue, proving z=1 draws are correctly ordered by creation order for same-z items

4. **Outlined rects** (z=2): Outlines around the filled rects in a bright color like white `{255, 255, 255, 255}`. These render on TOP of the filled rects (z=2 > z=1), visually confirming z-ordering.

5. **Crosshair lines** (z=3): Two diagonal lines across the full window in yellow `{255, 220, 0, 255}`. These render on top of everything (highest z), confirming lines work and z-ordering is global.

**Input handling (OnUpdate phase):**
A simple InputHandler system that reads SDL3_EventQueue and calls `cel_quit()` on Escape key press. Follow the exact pattern from the renderer example.

**cels_main:**
```c
cels_main() {
    cels_register(SDL3_Engine);
    SDL3_Renderable_use();
    cels_register(ShapeRenderer);
    cels_register(InputHandler);
    cels_session(World) {
        while (sdl3_should_run()) {
            float dt = sdl3_delta();
            cels_step(dt);
        }
    }
    printf("Draw primitives demo complete -- clean exit\n");
}
```

Note: `SDL3_Renderable_use()` is called AFTER `cels_register(SDL3_Engine)` but before the session. This registers the vtable so `sdl3_renderable()` returns a valid pointer.

**2. Update CMakeLists.txt:**

Add the draw-primitives example target in the examples section:
```cmake
add_executable(draw-primitives examples/draw-primitives/main.c)
target_link_libraries(draw-primitives PRIVATE cels-sdl3)
set_target_properties(draw-primitives PROPERTIES C_STANDARD 99 C_STANDARD_REQUIRED ON)
```

**AVOID:**
- Do NOT use immediate SDL draw calls. All draws must go through `sdl3_renderable()` vtable.
- Do NOT forget to call `SDL3_Renderable_use()` before the session -- without it, `sdl3_renderable()` will assert/return NULL.
- Do NOT use cel_update for draw calls. The vtable functions handle buffering internally.
