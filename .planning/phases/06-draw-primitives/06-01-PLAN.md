**3. Implementation in src/renderer/sdl3_draw.c:**

Static globals:
- `static SDL3_DrawBufferTable s_draw_table = {0};` for renderer-to-buffer lookup.
- `static SDL3_Renderable s_renderable = { ... };` singleton vtable, populated with function pointers.
- `static bool s_renderable_registered = false;` guard.

Draw buffer functions:
- `sdl3_draw_buffer_init`: Allocate `SDL3_DRAW_BUFFER_INITIAL_CAPACITY` commands via `malloc`, set count=0, capacity=initial, next_order=0.
- `sdl3_draw_buffer_clear`: Set count=0, next_order=0 (keep allocation).
- `sdl3_draw_buffer_push`: If count == capacity, double capacity via `realloc`. Assign `cmd.order = comp->draw_next_order++`. Append and increment count.
- `sdl3_draw_buffer_flush`: Sort commands by (z ascending, order ascending) via `qsort`. Then iterate sorted commands: for each, call `SDL_SetRenderDrawColor` with cmd color, then switch on type to call `SDL_RenderFillRect`, `SDL_RenderRect`, or `SDL_RenderLine`.
- `sdl3_draw_buffer_destroy`: `free(comp->draw_cmds)`, set pointer to NULL.

Draw table functions:
- `sdl3_draw_table_clear`: Set count=0.
- `sdl3_draw_table_add`: Append entry if count < SDL3_MAX_WINDOWS.
- `sdl3_draw_table_find`: Linear scan for matching renderer pointer.

qsort comparator `sdl3_draw_cmd_compare`: Compare by z first (ascending), then by order (ascending).

Vtable implementation functions (these buffer commands, not immediate SDL calls):
- `sdl3_impl_filled_rect(r, rect, color, z)`: Find buffer via `sdl3_draw_table_find(r)`, push `SDL3_DRAW_FILLED_RECT` command.
- `sdl3_impl_filled_rects(r, rects, colors, count, z)`: Loop `count` times, push one `SDL3_DRAW_FILLED_RECT` command per rect (each with its own color from the parallel array). This correctly handles per-shape color since SDL3 batch APIs use a single global color.
- `sdl3_impl_outlined_rect`: Same as filled_rect but with `SDL3_DRAW_OUTLINED_RECT` type.
- `sdl3_impl_outlined_rects`: Same as filled_rects pattern but with `SDL3_DRAW_OUTLINED_RECT`.
- `sdl3_impl_line(r, a, b, color, z)`: Find buffer, push `SDL3_DRAW_LINE` command.

Public API:
- `sdl3_renderable()`: Return `&s_renderable` (assert `s_renderable_registered`).
- `SDL3_Renderable_use()`: Populate `s_renderable` with the impl function pointers, set `s_renderable_registered = true`. This is called once by the developer at registration time.
- `sdl3_set_blend_mode(renderer, mode)`: Wrapper for `SDL_SetRenderDrawBlendMode(renderer, mode)`.

**AVOID:**
- Do NOT make SDL3_DrawCmd a separate ECS component. The draw buffer is embedded in SDL3_Renderer.
- Do NOT call SDL draw functions directly in vtable implementations. Always buffer.
- Do NOT use cel_query/cel_each in sdl3_draw.c (per-TU static ID constraint). Use the draw table lookup pattern.

- Option B: Free the draw buffer in sdl3_module.c WindowStateSystem where the component is accessible, before calling sdl3_renderer_destroy.

Use **Option B** -- it matches the existing pattern where WindowStateSystem manages the CLOSING->CLOSED transition with component access. **3. Modify SDL3_RenderClearSystem in sdl3_module.c:**

After the existing clear operations, add draw buffer clear AND draw table registration. The system already has `cel_each(SDL3_WindowComponent, SDL3_Renderer)` with mutable access via the implicit model. However, draw buffer clear is internal mutation (like SDL backbuffer writes -- per decision 05-01), so handle it similarly:

Build the draw table during the clear pass -- this is the same per-frame pass that already iterates all renderable windows. For each renderable window:
1. Call `sdl3_draw_table_add(SDL3_Renderer->renderer, SDL3_Renderer)` to register the mapping (the pointer to the SDL3_Renderer component gives access to the embedded draw buffer fields).
2. Reset draw buffer: set `draw_count = 0` and `draw_next_order = 0`.

**IMPORTANT:** The RenderClearSystem uses `cel_each` which gives const pointers. For the draw buffer reset, this is SDL-internal state mutation (not tracked by ECS), similar to how SDL_RenderClear mutates the SDL backbuffer without cel_update. The draw_count/draw_next_order reset and draw_table_add need mutable access. Use `cel_update(SDL3_Renderer)` block to wrap the buffer clear, OR cast away const for the internal fields since this is internal SDL3 module state (matching the precedent that SDL render calls don't use cel_update).

Actually, looking at the existing code more carefully: `SDL_SetRenderDrawColor` and `SDL_RenderClear` are called WITHOUT `cel_update` in RenderClearSystem because they modify SDL-internal state, not the ECS component struct. But resetting `draw_count` and `draw_next_order` modifies the actual component struct fields. So we MUST use `cel_update(SDL3_Renderer)` for the buffer reset.

Update the RenderClearSystem to:
```c
CEL_System(SDL3_RenderClearSystem, .phase = PreRender) {
    sdl3_draw_table_clear();

    cel_query(SDL3_WindowComponent, SDL3_Renderer);
    cel_each(SDL3_WindowComponent, SDL3_Renderer) {
        if (SDL3_WindowComponent->state == SDL3_WINDOW_MINIMIZED ||
            SDL3_WindowComponent->state == SDL3_WINDOW_CLOSING ||
            SDL3_WindowComponent->state == SDL3_WINDOW_CLOSED) continue;

        /* Register renderer-to-buffer mapping for vtable lookups during OnRender */
        cel_update(SDL3_Renderer) {
            sdl3_draw_table_add(SDL3_Renderer->renderer, SDL3_Renderer);
            SDL3_Renderer->draw_count = 0;
            SDL3_Renderer->draw_next_order = 0;
        }

        SDL_SetRenderDrawColor(SDL3_Renderer->renderer,
            SDL3_Renderer->clear_color.r,
            SDL3_Renderer->clear_color.g,
            SDL3_Renderer->clear_color.b,
            SDL3_Renderer->clear_color.a);
        SDL_RenderClear(SDL3_Renderer->renderer);
    }
}
```

**4. Add SDL3_DrawFlushSystem in sdl3_module.c:**

Add a new system at PostRender phase. Must be registered BEFORE SDL3_RenderPresentSystem in module init so it executes first within the PostRender phase.

```c
CEL_System(SDL3_DrawFlushSystem, .phase = PostRender) {
    cel_query(SDL3_WindowComponent, SDL3_Renderer);
    cel_each(SDL3_WindowComponent, SDL3_Renderer) {
        if (SDL3_WindowComponent->state == SDL3_WINDOW_MINIMIZED ||
            SDL3_WindowComponent->state == SDL3_WINDOW_CLOSING ||
            SDL3_WindowComponent->state == SDL3_WINDOW_CLOSED) continue;

        if (SDL3_Renderer->draw_count == 0) continue;

        sdl3_draw_buffer_flush(SDL3_Renderer);
    }
}
```

Note: `sdl3_draw_buffer_flush` is called from sdl3_module.c (which has component access) and receives the mutable SDL3_Renderer pointer. The flush function in sdl3_draw.c reads draw_cmds/draw_count, sorts, and issues SDL calls. The flush does not need cel_update because it doesn't modify tracked ECS state -- it reads the buffer and calls SDL functions (same pattern as SDL_RenderPresent).

Wait -- the `cel_each` gives const pointers. The flush function needs mutable access to sort the commands in-place (qsort). Wrap in `cel_update(SDL3_Renderer)`:

```c
        cel_update(SDL3_Renderer) {
            sdl3_draw_buffer_flush(SDL3_Renderer);
        }
```
