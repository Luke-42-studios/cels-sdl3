  <action>
  Replace `examples/minimal/main.c` with a comprehensive window lifecycle test. The app exercises:

  1. **Single window creation** with state verification
  2. **Multi-window coexistence** with independent state
  3. **Event-driven state transitions** via SDL_PushEvent (headless testing pattern)
  4. **Clean destruction** via session scope exit

  The app must run under `SDL_VIDEODRIVER=dummy` (headless, no display required).

  Structure the example as follows:

  ```c
  #include <cels/cels.h>
  #include <cels_sdl3.h>
  #include <SDL3/SDL.h>
  #include <stdio.h>
  #include <assert.h>
  ```

  **World composition -- two windows:**
  ```c
  CEL_Compose(World) {
      SDL3Context(.video = true) {}
      SDL3Window(.title = "Main Window", .width = 800, .height = 600) {}
      SDL3Window(.title = "Debug View") {}  /* gets 1280x720 default */
  }
  ```

  **A verification system** that runs at OnLoad phase, queries SDL3_WindowComponent, and prints state information for each window entity. This system should:
  - `cel_query(SDL3_WindowComponent)` and `cel_each(SDL3_WindowComponent)` to iterate windows
  - On the first frame, print each window's title (via `SDL_GetWindowTitle()`), dimensions, window_id, and state
  - Verify each window's state is SDL3_WINDOW_READY
  - Count the number of window entities (should be 2)
  - Print "PASS: N windows created, all READY" or "FAIL: ..." accordingly

  **A test system** that runs at OnUpdate phase and exercises state transitions using SDL_PushEvent on frame 2:
  - Get the first window's SDL_WindowID from its SDL3_WindowComponent
  - Push an `SDL_EVENT_WINDOW_CLOSE_REQUESTED` event targeting that window via:
    ```c
    SDL_Event ev = {0};
    ev.type = SDL_EVENT_WINDOW_CLOSE_REQUESTED;
    ev.window.windowID = first_window_id;
    ev.window.timestamp = SDL_GetTicksNS();
    SDL_PushEvent(&ev);
    ```
  - NOTE: The pushed event will be available for Phase 4 to route. For Phase 2 testing, we call `sdl3_window_handle_event()` directly on the component since we don't have event polling yet.
  - Actually, since sdl3_window_handle_event is in sdl3_internal.h (internal), and the example is a consumer -- the example should NOT call internal functions directly. Instead, the verification system should observe the state machine's CLOSING -> CLOSED behavior from the SDL3_WindowStateSystem.

  **Revised approach for Phase 2 testing without event routing:**
  Since Phase 2 doesn't have event polling (that's Phase 3/4), the example should:
  1. Verify window creation works (state == READY) on frames 1-2
  2. Run a fixed number of frames (5 frames) to prove the loop works with windows
  3. Verify multi-window coexistence (2 independent windows, each with own SDL_Window)
  4. Let session exit handle clean destruction
  5. Print pass/fail results

  The state transition testing (minimize, resize, close events) will be fully exercised in Phase 4 when event routing exists. For Phase 2, we verify the creation chain and the queryability.

  **Main function:**
  ```c
  cels_main() {
      cels_register(SDL3_Engine);
      cels_session(World) {
          int frames = 0;
          while (cels_running() && frames < 5) {
              cels_step(0.016f);
              frames++;
          }
      }
      printf("Session complete -- windows destroyed via scope exit\n");
  }
  ```

  The CEL_System declarations must be in the example .c file (consumer TU), which is valid because the example links against cels-sdl3 and the system types are registered in the consumer's TU. Follow the pattern from cels-ncurses examples where consumer systems query provider components.

  Print output summary at the end:

  ```
  Window 2: "Debug View" 1280x720 id=M state=READY
  PASS: 2 windows created, all READY
  Session complete -- windows destroyed via scope exit
  ```
