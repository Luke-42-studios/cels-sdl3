**1. Create test PNG asset:**

Generate a simple test PNG image programmatically using SDL3 surface API (or use a minimal PNG from any available method). The image should be recognizable and useful for demonstrating features:

Option A (preferred -- generate at build time is overkill, just create a simple file): Create a small (64x64 or 128x128) PNG file at `examples/textures/assets/test.png`. Use any method available:
- Write a tiny C program that creates an SDL_Surface, fills it with a colorful pattern (e.g., 4 colored quadrants: red, green, blue, yellow), saves it with `IMG_SavePNG`, and run it once.
- Or use Python/ImageMagick if available: `convert -size 64x64 xc:red xc:green xc:blue xc:yellow +append -append test.png`
- Or create the PNG bytes directly using a minimal PNG encoder.

The image should have distinct regions (like colored quadrants) so that source rect sub-image rendering is visually verifiable -- you can see "I'm rendering just the top-left red quadrant."

Include some transparent pixels if possible (e.g., one quadrant with 50% alpha) to test alpha blending. If creating transparency is difficult, a fully opaque image is fine -- per-sprite alpha will still be exercised via the `alpha` field.

**2. Create examples/textures/main.c:**

Follow the established example app structure (see examples/renderer/main.c for reference):
- Header comment explaining what the example demonstrates
- World composition with a single SDL3Window + multiple SDL3_Sprite entities on the SAME window entity
- Input handler system for Escape key
- cels_main with register, session, loop

**Important design constraint:** SDL3_Sprite entities must live on the SAME entity as the window (same entity that has SDL3_Renderer and SDL3_WindowComponent). This is because the TextureLoadSystem queries `SDL3_Sprite, SDL3_Renderer, SDL3_WindowComponent` on the same entity. To have multiple sprites on one window, the example needs to use multiple entities that EACH have the window's renderer. However, this conflicts with how CELS works -- each entity has at most one of each component type.

**Resolution:** Since each entity can only have ONE SDL3_Sprite, demonstrating multiple textures requires either:
- Multiple window entities (each with one sprite) -- not ideal
- A single sprite that shows different features over time (rotation animation, etc.)
- Creating the sprite entity separately and associating it with the window's renderer

The simplest approach: Use a SINGLE sprite on the window entity that demonstrates all features. Use keyboard input to cycle through different rendering modes:

```
Keys:
  1 - Full texture at (200, 100, 256, 256), no rotation, no flip, alpha=255
  2 - Source rect top-left quadrant at (200, 100, 256, 256)
  3 - Rotated 45 degrees at (200, 100, 256, 256)
  4 - Flipped horizontally at (200, 100, 256, 256)
  5 - Semi-transparent (alpha=128) at (200, 100, 256, 256)
  Escape - close
```

The example system reads key events and updates the sprite's properties via `cel_update(SDL3_Sprite)`.

**World composition:**
```c
CEL_Compose(World) {
    SDL3Window(.title = "Textures Demo", .width = 800, .height = 600,
               .context = true, .target_fps = 60) {
        cel_has(SDL3_Sprite,
            .texture_path = "test.png",
            .dst_rect = { .x = 200, .y = 100, .w = 256, .h = 256 },
            .flip = SDL_FLIP_NONE,
            .alpha = 255
        );
    }
}
```

Note: `cel_has(SDL3_Sprite, ...)` inside the `SDL3Window(...){}` block attaches the sprite to the window entity, which already has SDL3_Renderer and SDL3_WindowComponent.

**SpriteController system (OnUpdate phase):**
Queries SDL3_EventQueue and SDL3_Sprite. Reads keyboard events and modifies sprite parameters:
```c
CEL_System(SpriteController, .phase = OnUpdate) {
    cel_query(SDL3_EventQueue, SDL3_Sprite);
    cel_each(SDL3_EventQueue, SDL3_Sprite) {
        bool modified = false;
        bool should_quit = false;

        /* Temporary copies of sprite params to modify */
        SDL_FRect src = {0};
        double angle = 0;
        SDL_FlipMode flip = SDL_FLIP_NONE;
        Uint8 alpha = 255;

        for (int i = 0; i < SDL3_EventQueue->count; i++) {
            const SDL_Event* ev = &SDL3_EventQueue->events[i];
            if (ev->type != SDL_EVENT_KEY_DOWN || ev->key.repeat) continue;

            switch (ev->key.key) {
            case SDLK_1:  /* Full texture, no effects */
                src = (SDL_FRect){0, 0, 0, 0};
                angle = 0; flip = SDL_FLIP_NONE; alpha = 255;
                modified = true;
                printf("Mode: full texture\n");
                break;
            case SDLK_2:  /* Top-left quadrant (source rect) */
                src = (SDL_FRect){0, 0, 32, 32}; /* or half the texture size */
                angle = 0; flip = SDL_FLIP_NONE; alpha = 255;
                modified = true;
                printf("Mode: source rect (top-left quadrant)\n");
                break;
            case SDLK_3:  /* Rotated 45 degrees */
                src = (SDL_FRect){0, 0, 0, 0};
                angle = 45.0; flip = SDL_FLIP_NONE; alpha = 255;
                modified = true;
                printf("Mode: rotated 45 degrees\n");
                break;
            case SDLK_4:  /* Flipped horizontally */
                src = (SDL_FRect){0, 0, 0, 0};
                angle = 0; flip = SDL_FLIP_HORIZONTAL; alpha = 255;
                modified = true;
                printf("Mode: flipped horizontally\n");
                break;
            case SDLK_5:  /* Semi-transparent */
                src = (SDL_FRect){0, 0, 0, 0};
                angle = 0; flip = SDL_FLIP_NONE; alpha = 128;
                modified = true;
                printf("Mode: semi-transparent (alpha=128)\n");
                break;
            case SDLK_ESCAPE:
                printf("Escape pressed -- closing\n");
                should_quit = true;
                break;
            default:
                break;
            }
        }

        if (modified) {
            cel_update(SDL3_Sprite) {
                SDL3_Sprite->src_rect = src;
                SDL3_Sprite->angle = angle;
                SDL3_Sprite->flip = flip;
                SDL3_Sprite->alpha = alpha;
            }
        }

        if (should_quit) {
            cel_quit();
        }
    }
}
```

Adjust the source rect dimensions in case 2 based on the actual test image size (if 64x64, use `{0, 0, 32, 32}` for top-left quadrant).

**cels_main:**
```c
cels_main() {
    cels_register(SDL3_Engine);
    cels_register(SpriteController);

    sdl3_set_asset_base_dir("assets");

    cels_session(World) {
        while (sdl3_should_run()) {
            float dt = sdl3_delta();
            cels_step(dt);
        }
    }
    printf("Textures demo complete -- clean exit\n");
}
```

Note: `sdl3_set_asset_base_dir("assets")` sets the base directory so the sprite's `texture_path = "test.png"` resolves to `"assets/test.png"`. The working directory when running the example is `cmake-build-debug/`, so the path needs to resolve correctly. Either:
- Use an absolute path constructed from argv[0] or `SDL_GetBasePath()`
- Or copy assets to the build directory via CMake
- Or set the base dir to the source-relative path

The simplest approach: Set the base dir using `SDL_GetBasePath()` combined with the relative source path, OR use CMake to copy the assets directory to the build output. Use CMake's `file(COPY ...)` or `configure_file` or a custom command.

**3. Update CMakeLists.txt:**

Add the textures example target:
```cmake
add_executable(textures examples/textures/main.c)
target_link_libraries(textures PRIVATE cels-sdl3)
set_target_properties(textures PROPERTIES C_STANDARD 99 C_STANDARD_REQUIRED ON)
```

Add a post-build command to copy assets to the build directory so the example can find them at runtime:
```cmake
add_custom_command(TARGET textures POST_BUILD
    COMMAND ${CMAKE_COMMAND} -E copy_directory
    ${CMAKE_CURRENT_SOURCE_DIR}/examples/textures/assets
    $<TARGET_FILE_DIR:textures>/assets
)
```

This copies `examples/textures/assets/` to `cmake-build-debug/assets/` (next to the executable) so `sdl3_set_asset_base_dir("assets")` resolves correctly when running from the build directory.

**AVOID:**
- Do NOT put sprites on separate entities from the window. The TextureLoadSystem queries SDL3_Sprite + SDL3_Renderer + SDL3_WindowComponent on the same entity.
- Do NOT hardcode absolute paths to test images. Use sdl3_set_asset_base_dir with a relative path.
- Do NOT skip the CMake asset copy command. Without it, the example can't find the test image at runtime.
- Do NOT use `IMG_Init()`. SDL3_image 3.x has no init function.
