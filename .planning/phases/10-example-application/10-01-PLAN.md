**1. Create examples/demo/main.c**

Write a complete demo application (~250-350 lines) following the established example patterns (see examples/renderer/main.c for the canonical pattern). The demo composes ALL v1 features into a mini landscape scene at 1280x720.

**Structure the file in this order:**

```
Includes: cels/cels.h, cels_sdl3.h, stdio.h
Scene state: PlacedShape struct, static array, color cycling
World composition: window + font load + scene entities
DemoInput system (OnUpdate): ESC to quit, mouse click to place shapes
DemoRenderer system (OnRender): landscape scene + click-placed shapes
FPSUpdater system (OnUpdate): update FPS text string
Main: register, session, loop, exit message
```

**Scene state (static globals):**

```c
typedef struct PlacedShape {
    float x, y;
    SDL_Color color;
} PlacedShape;

#define MAX_PLACED_SHAPES 256
static PlacedShape s_placed[MAX_PLACED_SHAPES];
static int s_placed_count = 0;
static int s_color_index = 0;

static const SDL_Color SHAPE_COLORS[] = {
    {255, 100, 100, 255},  /* soft red */
    {100, 255, 100, 255},  /* soft green */
    {100, 100, 255, 255},  /* soft blue */
    {255, 255, 100, 255},  /* yellow */
    {255, 100, 255, 255},  /* magenta */
    {100, 255, 255, 255},  /* cyan */
};
#define NUM_SHAPE_COLORS (sizeof(SHAPE_COLORS) / sizeof(SHAPE_COLORS[0]))
```

**World composition (CEL_Compose(World)):**

Use `cel_remember` for window entity ID and init-once guard. Create a 1280x720 window titled "cels-sdl3 Demo" with `.context = true, .target_fps = 60`.

After window creation (guarded by `*init_done`):
1. Load font: `sdl3_font_load(0, "examples/assets/PressStart2P-Regular.ttf", 16.0f)`
2. Set sky-blue clear color on the renderer via `cel_update(SDL3_Renderer)` -- use a light sky blue like `{135, 206, 235, 255}`
3. Create sprite entity for the tree: entity with `SDL3_Sprite` component, `.texture_path = "examples/assets/tree.png"`, positioned in the landscape (e.g., `dst_rect = {500, 380, 48, 64}` or similar -- above the ground line), `.alpha = 255`, `.flip = SDL_FLIP_NONE`
4. Create three text entities (title, FPS, instructions), each with `SDL3_Text` and `SDL3_TextHandle` components:
   - Title: `.string = "cels-sdl3 Demo"`, `.font_id = 0`, `.color = {255, 255, 255, 255}`, `.x = 16`, `.y = 16`
   - FPS: `.string = "FPS: --"` (pointer to a static buffer `s_fps_buf`), `.font_id = 0`, `.color = {255, 255, 0, 255}`, `.x = 16`, `.y = 40`
   - Instructions: `.string = "Click to plant / ESC to quit"`, `.font_id = 0`, `.color = {200, 200, 200, 255}`, `.x = 16`, `.y = 64`

For creating sprite and text entities: use `cels_entity_new()` and `cels_entity_set_component()` with the appropriate component IDs. Follow the pattern from the Phase 7 and Phase 8 plans -- sprites live on the window entity (same entity that has the renderer), and text entities are separate entities with SDL3_Text + SDL3_TextHandle.

IMPORTANT for text entity creation: SDL3_TextHandle must be initialized with all fields zeroed (`.ttf_text = NULL`, all last_* fields zeroed). The text render system will create the TTF_Text handle on first encounter.

IMPORTANT for sprites: Per Phase 7 Plan 01, TextureLoadSystem queries `SDL3_Sprite, SDL3_Renderer, SDL3_WindowComponent` on the same entity. So the sprite MUST live on the window entity. Set the sprite component on the window entity using `cels_entity_set_component`.

Store entity IDs for the FPS text entity via `cel_remember` so the FPSUpdater system can update its string.

**DemoInput system (CEL_System, .phase = OnUpdate):**

Query `SDL3_EventQueue`. Iterate `events[0..count-1]`:
- `SDL_EVENT_KEY_DOWN` with `key == SDLK_ESCAPE`: call `cel_quit()`
- `SDL_EVENT_MOUSE_BUTTON_DOWN`: if `s_placed_count < MAX_PLACED_SHAPES`, add a PlacedShape at `(ev->button.x, ev->button.y)` with color from `SHAPE_COLORS[s_color_index % NUM_SHAPE_COLORS]`, increment both counters

**DemoRenderer system (CEL_System, .phase = OnRender):**

Get the draw vtable: `const SDL3_Renderable* draw = sdl3_renderable();`

Query `SDL3_Renderer, SDL3_WindowComponent`. For each renderable window (skip MINIMIZED/CLOSING/CLOSED):

Draw the landscape scene using the Renderable vtable:
1. Ground (filled rect, z=0): `{0, 480, 1280, 240}` in grass green `{76, 153, 0, 255}`
2. Horizon line (line, z=0): from `{0, 480}` to `{1280, 480}` in dark green `{60, 120, 0, 255}`
3. Building body (filled rect, z=1): `{200, 380, 120, 100}` in brown `{160, 82, 45, 255}`
4. Building outline (outlined rect, z=1): same rect in darker brown `{100, 50, 25, 255}`
5. Sun (outlined rect, z=1): `{1050, 80, 80, 80}` in golden yellow `{255, 220, 50, 255}`
6. Click-placed shapes (filled rect, z=3): loop `s_placed[0..s_placed_count-1]`, draw 16x16 filled rects centered on click position with each shape's color

Note: Sprites render via the SpriteRenderSystem (automatic, no code needed here). Text renders via the TextRenderSystem (automatic). Both happen at OnRender phase alongside this system. The z-ordering for draw primitives is independent of sprite/text rendering -- sprites and text render directly to the SDL renderer during OnRender, while draw primitives buffer and flush at PostRender (DrawFlushSystem). This means draw primitives will render ON TOP of sprites/text. Design the scene knowing this: the ground, building, sun, and placed shapes will appear above the tree sprite. This is acceptable -- the tree is a background element.

If this visual ordering is problematic, the alternative is to draw the tree manually using the renderable vtable instead of using SDL3_Sprite (but that loses TXTR-02 validation). Keep the sprite approach -- it validates the texture system even if layering isn't ideal.

**FPSUpdater system (CEL_System, .phase = OnUpdate):**

Use a `static char s_fps_buf[32] = "FPS: --"` (declared at file scope, NOT local to the system). Read `cel_read(SDL3_FrameState)` to get `smoothed_fps`. Format via `snprintf(s_fps_buf, sizeof(s_fps_buf), "FPS: %.0f", frame->smoothed_fps)`.

The FPS text entity's SDL3_Text.string points to `s_fps_buf` (a stable static pointer). When the system updates the buffer contents, the string pointer doesn't change, but the text content does. The text render system detects changes by comparing the pointer with `last_string` -- since the pointer is the SAME, the text system won't auto-detect the change.

To trigger cache invalidation: the system needs to update the text entity's SDL3_Text component. Use the stored FPS text entity ID from World composition. Query that entity and `cel_update(SDL3_Text)` to trigger the text render system's sync check. The sync function `sdl3_text_sync` compares the actual string via `TTF_SetTextString` which internally checks if the string changed.

Alternative simpler approach: Update the SDL3_Text.string pointer to point to a rotating pair of static buffers. When the pointer changes, the text system detects it via `last_string != string` and calls `TTF_SetTextString`. This is the cleanest pattern:

```c
static char s_fps_bufs[2][32] = { "FPS: --", "FPS: --" };
static int s_fps_buf_idx = 0;
```

Each frame, format into the next buffer and flip the index. Update the text entity's string pointer to the new buffer. The pointer change triggers cache invalidation.

Or even simpler: just use `cel_update(SDL3_Text)` to mark the component dirty. The text render system syncs via `sdl3_text_sync` which calls `TTF_SetTextString` -- that function internally checks if the string content changed and only recreates if needed.

Use the `cel_update` approach -- it's the documented pattern from Phase 8.

**Main (cels_main):**

```c
cels_main() {
    cels_register(SDL3_Engine);
    cels_register(DemoInput);
    cels_register(DemoRenderer);
    cels_register(FPSUpdater);
    cels_session(World) {
        while (sdl3_should_run()) {
            float dt = sdl3_delta();
            cels_step(dt);
        }
    }
    printf("cels-sdl3 Demo -- clean exit\n");
}
```
